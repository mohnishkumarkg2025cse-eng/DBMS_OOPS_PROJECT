**Purpose:** Establish the behavior baseline for the integrated product plan.

## Baseline and scope

- The worktree contained uncommitted Dashboard, Applicants, Policies, stylesheet, progress, and changelog changes when inspected. They are preserved; T001 made no source changes.
- No `StyleSheetTest` or `StyleClassUsageTest` was found in the test inventory recorded in `PROGRESS.md`; existing UI icon test is `IconsTest`.
- The latest recorded full test run passed 61 tests with no skips. This is not evidence of GUI interaction; no action in this inventory was manually clicked or visually inspected.
- No standalone audit/architecture artifact was located in the workspace search. The findings above are based on `PROGRESS.md` and direct source inspection of the UI handlers, not an assertion that a separate audit was re-read.
- Protected local configuration and environment-variable values were not inspected or included.

## Implementation priorities confirmed by the inventory

1. Establish explicit program ownership and safe legacy handling before using selected program as a filter.
2. Align seed/clear wording with actual preservation behavior; mark demo-owned records and never delete evaluation history by accident.
3. Make applicant creation/schema validation program-aware and scope evaluation pools before adding more scenarios.
4. Keep stored evaluations and immutable policy versions authoritative; make historical explanation and comparison semantics explicit.
5. Persist/rebuild dashboard aggregate snapshots only after defining invalidation and freshness rules against evaluation records.
6. Test every action end-to-end; current event handlers and unit tests do not establish full JavaFX workflow success.
